# Recscene — decisions log

**Name: Recscene** — "Record the screen. Make it a scene." Chosen 2026-11-17. recscene.com, .app, .io, .dev and .co were unregistered that day and no app or product used the name; trademark registers (USPTO, EUIPO) still need a search before launch.

## Settled (2026-11-17)

**Product**
- A paid macOS app for people who make product demos, tutorials and bug reports: record the screen, get a polished video without editing skills.
- The feature set follows the Screen Studio study in `research/` (292 specs). Recscene matches that behaviour feature for feature unless a line here says otherwise, so the specs are the acceptance criteria.
- Data stays on the user's Mac. A project is a `.recscene` folder bundle (raw screen, camera and audio files plus a JSON project document). Cloud is only for sharing a rendered video by link, and only after M2.
- Milestones:
  - **M1 — daily driver:** record the screen with clicks and keys captured, automatic zooms, cursor smoothing, trim, background and padding, export MP4. Used for two weeks for the author's own demos.
  - **M2 — private beta:** camera with layouts and cutout, microphone, masks, captions, GIF export, presets, 10–30 testers.
  - **M3 — launch:** licensing, auto-update, shareable links, landing page, transcript editing, voice-overs.

**Platform and stack**
- macOS first, Apple silicon and Intel. Windows is not planned until after M3.
- Electron + electron-vite + React 19 + TypeScript. Reason: the design is HTML-native, the reference app proves the architecture at this feature set, and the editor UI changes far more often than the capture code.
- Screen, camera and audio capture go through a native Swift helper (ScreenCaptureKit, AVFoundation) under `native/`, talking to the main process over a local socket or stdio. Electron's `desktopCapturer` is not used: it cannot capture clicks, keystrokes, cursor positions or 60 fps at full resolution reliably.
- Rendering (zooms, cursor, layouts, background) happens in the renderer; the preview is DOM and CSS transforms, export redraws every frame on a canvas with the same maths and encodes H.264 through WebCodecs (the platform encoder) into an MP4 stream. The native helper joins the mixed audio as AAC. No ffmpeg in JavaScript. **Amended 2026-11-17:** the earlier plan to encode in the helper is replaced by WebCodecs, which keeps rendering and encoding in one process.
- Layering: `src/core` (pure domain, tested) → `src/main` (Electron, files, native bridge) → `src/preload` (typed bridge) → `src/renderer` (React). Core never imports the layers above it.
- Tooling matches the author's other projects: npm, Node 24, ESLint flat config, vitest with v8 coverage, GitHub Actions on push and PR.

**Design**
- Dark is the editor default; light is the default for export, settings and the project list. Both come from one token set; nothing is styled outside the tokens.
- Breakpoints: laptop 1280×800 (rail 68, inspector 312, timeline 236), tablet 1024×768, mobile 390×844 (companion role only: record remotely, light edits).
- Track colours: zooms purple, clips yellow, camera layouts pink, masks teal, shortcuts blue, captions green, voice-overs orange.

## Amendments

**2026-11-17 (recording section built).** Specs 1–5, 7, 13, 15–17 and 21–41 are implemented. Of the rest: 6 (iPhone/iPad over USB) and 8–12 (camera at record time) move to M2 with the camera work; 14 (mono conversion) belongs to the editor audio panel; 18–19 (system audio from selected apps, external device audio) need a second audio-only capture stream and move to M2; 20 (recording engine auto/modern/legacy) does not apply, Recscene has one engine; 42–47 (quick export widget) wait for export (233–245). Spec 41's `actionAfterRecording` is stored but only `create-project` behaves until then. Keystroke capture needs Input Monitoring; clicks and cursor are polled and need nothing.

**2026-11-17 (projects home built).** On launch, unfinished recordings (spec 40) show in the home's banner with Recover and Delete instead of a modal dialog; File › Recover Unfinished Recordings keeps the dialog. Project thumbnails are PNGs cached inside the bundle (`thumbnail.png`), drawn from the footage once and refreshed from the edited frame on every save. Deleting a project moves the bundle to the macOS Trash. The projects folder preference (`projectsFolderPath`, spec 255) lives in the home's storage box until the Settings window exists.

**2026-11-17 (camera recording built).** The webcam is recorded by the helper into `camera.mov` (H.264, 30 fps, tallest format at or under the 720/1080 preference) on the screen recording's clock: frames before the screen's first frame are dropped and pauses are cut out, so the two files line up without an offset. Spec 9's "record muted camera" needs no option: the camera's own audio is never recorded, the microphone is the only voice source. The preview bubble is a separate always-on-top window fed by the renderer's own camera stream, excluded from the capture like every app window. Camera access is asked by the app first (Electron's prompt), then by the helper; both are attributed to the app by macOS.

**2026-11-17 (camera layouts built).** The camera is composited by the same code path as the stage: a box computed per frame from the effective layout (timeline layout, else the default, else hidden), animated between layouts by a spring and faded when hidden; the split layout is a Recscene addition from the Camera board (screen and camera side by side, ½·½ or ⅔·⅓, flip). Layouts live at `project.layouts` (the competitor's `scenes[].layouts`; Recscene has one scene). The camera's own time is the screen time minus `cameraDelayMs`. Cutout, looks, sharpen, face tracking and hide-during-silence are deferred: cutout and looks need the GPU renderer and a matting model, silence needs the audio panel's speech ranges.

**2026-11-17 (masks built).** Mask regions are stored as fractions of the full recording frame, so they survive crops and resolution changes; the renderers map them through the crop. The stage blurs with `backdrop-filter` and dims with an even-odd clip path, the export draws the same maths on the canvas (blur with padded source so edges do not fade). Masks live at `project.masks` and cannot overlap in time (one renders at a time). Spec 197's shift detection is deferred; the board's auto masks (4.x) too.

**2026-11-17 (shortcuts built).** Keystroke labels are drawn from the recorded key events (`recording.keys`, labels like ⇧⌘P from the helper) at the bottom centre of the screen box, outside the zoom, for 1.4 s with a 0.3 s fade; the latest press replaces the previous one. Hidden occurrences follow the competitor's `hiddenShortcuts` map keyed by the press time. The board's "disable by kind" is a Recscene addition (`disabledShortcutKinds`). Spec 199's enable question uses the window confirm until the editor has its own dialog component.

**2026-11-18 (audio built).** The mix is built with Web Audio in both preview (MediaElementSource graph) and export (OfflineAudioContext): master gain, microphone through the mode's chain (high-pass, low-pass, compressor, make-up, peak normalisation), system audio decoded from the screen file, background music looping from project start in output time, click sounds. The 17 bundled tracks are synthesized placeholders generated with ffmpeg (`resources/music`), named after the competitor's categories; real royalty-free music can replace the files without code changes. Own tracks are copied into the bundle; the library folder lives under the app's user data and is served by `recscene-media://library/<file>`.

**2026-11-18 (captions built; Q2 settled).** The transcription engine is Apple's SpeechAnalyzer/SpeechTranscriber (macOS 26+), run by the helper on the microphone file with word time ranges; no model download beyond the system's own speech assets, nothing leaves the Mac, and no Speech Recognition permission prompt is needed for file transcription. Whisper is not bundled. The transcript lives in project.json (`project.transcript`, words with hidden and filler flags) so edits are undoable like everything else; cues are built on the fly. Edit-by-transcript cuts are ordinary clip cuts.

**2026-11-18 (presets built).** A preset is a JSON file `<name>.recscenepreset` in `~/Documents/Recscene Presets` (preference `presetsFolderPath`) holding a copy of the inspector config without the recording-specific keys (range, crop, typing suggestions, hidden shortcuts, background image, background audio file); applying copies the keys over the project's config and keeps those. New recordings start from the default preset, else the last saved project's config when `useLastProjectConfigForNewProjects` is on, else the built-in defaults.

**2026-11-18 (settings built).** All app preferences live in one typed model (`src/core/settings.ts`) read from the preferences file; the Settings window writes through one IPC and broadcasts `prefs:changed` so open editors follow without a restart. Global shortcuts are registered from the preferences (remappable, spec 66) with the record/flag/prompter ids; editor shortcuts are overridden per action id on top of the registry. Appearance sets Electron's theme source and the renderer's `data-theme`. There is no support server: "Share diagnostics info" copies the report to the clipboard, update checks only state the version until signed builds exist, and analytics is a stored flag that sends nothing.

**2026-11-18 (quick export and project files built).** After a recording the quick export widget shows by default (`showQuickExportWidget`, spec 41); it is its own always-on-top window that runs the same export engine as the editor with a `quick` target that writes to `~/Movies/Recscene` without a dialog. The project is written before the widget appears, so Keep/Delete only decides whether the bundle stays. Zipping uses `ditto` and puts a file URL on the pasteboard; `.recscene` bundles are registered as a package document type and drops go through one open-path check.

**2026-11-18 (editor leftovers built).** Cursor types come from the helper polling `NSCursor.currentSystem` at 20 Hz and matching its image against the standard cursors (`events.json` `cursorTypes`); app-drawn cursors read as the pointer. Cursor sets are SVG sprites drawn in code (24 sets, 9 types), not bundled images. Device mockups are drawn from geometry (bezel fractions, notch, chin, stand) rather than photographed frames, so they scale to any export size and need no assets; Perfect mode lists frames whose screen aspect matches the recording. Screen motion blur is a CSS blur in the preview and a canvas filter on export, driven by the camera spring's velocity. Reel mode is a preview overlay only; 9:16 export is the aspect picker's job.

**2026-11-18 (camera extras built).** Hide-during-silence uses a plain RMS level detector on the decoded microphone track (−38 dBFS, 30 ms windows, runs joined within 300 ms, padded 150 ms), computed in the renderer when the toggle is on; the resulting silence gaps are passed to the stage and the export, which swap the effective layout to hide-camera inside a gap unless the microphone is muted, the camera fills the frame or a layout already hides it. Camera looks are colour filters (brightness, contrast, saturation, sepia, hue, grayscale mixed by the intensity) rather than 3D LUTs, applied as a CSS filter on the preview's camera element and `ctx.filter` on export; sharpen is a 3 × 3 convolution in one shared SVG filter element. Custom .cube LUTs and the preset studio wait for a GPU path.

**2026-11-18 (voice-overs built).** A voice-over is a mono 16-bit WAV written into the bundle (`voiceover-<n>.wav`) and listed at `project.voiceOvers` with the competitor's fields (`sourceStartMs`, `voiceoverDurationMs`, `volume`, `attachMode` first-frame/all-frames, `hideRecording`, `isDisabled`). Files are in source time: the Voiceover editor plays the clip at 1 ÷ clip speed so the source advances in real time while the microphone is captured through Web Audio (no helper involvement, microphone access via `getUserMedia`), and a recording is limited to the current clip and stops at the next voice-over. A synchronized voice-over therefore plays at the clip's speed and loses cut-out parts; an independent one runs whole at 1× from where its first frame lands. Preview plays one audio element per file; export schedules each segment in the offline mix, and "Hide & Mute original recording" ducks the microphone and system audio with gain automation and hides the camera. AI voice-overs (Speechify) are not built.

**2026-11-18 (sign-in built; Q1 narrowed).** Accounts use Supabase Auth with Google sign-in, the same setup as Sparehour: the app asks Supabase for a PKCE authorisation URL, opens it in the user's default browser (never an embedded web view, which Google blocks), and the consent lands back in the app, in packaged builds through the `recscene://auth/callback` deep link and in development through a loopback listener on `http://127.0.0.1:51797/auth/callback` (macOS only routes custom schemes to signed bundles). The main process exchanges the code and keeps the session in `auth.json` under the app data folder, encrypted with Electron's `safeStorage`; the renderer only sees the account state over IPC. Each Mac registers a seat in a `devices` table (row-level security: a user reads and frees only their own rows) so the Account tab can list devices and deactivate one (spec 277); signing out frees this Mac's seat. Licence keys, email codes, Microsoft and SSO are not built; the licensing model (Q1) is still open, so nothing is gated on being signed in and the Account tab says so. The Supabase project URL and anon key come from `MAIN_VITE_SUPABASE_URL` / `MAIN_VITE_SUPABASE_ANON_KEY` at build time (`.env`, see `.env.example`); without them the tab explains that sign-in is not set up in this build.

## Open
- **Q1** Licensing model: one-time with a year of updates versus subscription. Sign-in is decided (Google through Supabase, 2026-11-18); what a signed-in account entitles, trial limits and prices are still to decide before M3.
- **Q2** Transcription and captions: on-device (whisper.cpp) versus a cloud service. Lean on-device for privacy; decide at M2.
- **Q3** Whether the tablet and mobile designs ship at all in M1–M3 or stay as companion designs. Default: not before M3.
- **Q4** Code signing and notarisation account: personal Apple Developer account, to be set up before M2 testers receive a build.
